## 已驗證的行為

- 同一回合重連保留同一組地圖資源及視角，避免重建與重新暖機。
- 模擬前景執行緒停頓 3.3 秒後，先處理已排隊的更新，不因此丟棄健康連線；真正斷線仍走重連流程。
- 停止本機移動後，沒有新快照時不會被同一筆舊座標每幀拉回。
- 轉向後的第一個畫面維持角色構圖；降落時使用連續高度推估。
- 本機槍口回饋可立即出現，不能更改伺服器彈藥、命中或傷害。
- 空間索引的碰撞結果與原完整掃描等價；渲染不能吃掉待送出的跳躍。
- 固定 48 彈道／6 爆炸資源池；持續射擊不建立新的 GPU 緩衝。
- 傷害提示可以重啟並淡出，不強制同步排版、不留下永久紅色遮罩。
- 實際隔離 HTTP／WS 雙人流程通過：降落觸控轉向、三指移動／轉向／射擊、單一視角取消事件不影響其他手指、同局重連不重播歷史彈道。CDP 無法只結束單一觸點，該取消事件用原生觸點的 pointer ID 注入；全部放開仍使用原生觸控事件。

## 伺服器合成 CPU 預算

沿用 `scripts/bench-battle.py` 的 3 房／32 真人／48 參與者、20 秒模擬負載，單核估算使用率 20.5%，tick P95 25.18ms、最大 45.00ms。伺服器固定步長為 50ms；本次未修改規則或 tick 頻率。此數據只涵蓋本機模擬與快照，不含 HTTP、語音、Cloudflare 路徑，也不是正式主機的即時使用率。


## 第二輪動作／畫面打磨

第二輪在同一固定負載下，每階段取樣 60 幀，桌面最多 38 次繪製、手機模擬最多 36 次；降落、移動、射擊各階段均沒有新增 GPU 緩衝。角色由原本簡化部件增加至 42 部件，但仍由四組共享批次繪製。這次重點是增加細節並守住資源預算，不宣稱相對上一版所有畫面都更快。

另驗證準星目標投影在畫面正中心、武器仰角正確、ADS 第一幀僅移動全程的一部分、角色轉向不改變構圖、停止移動不向舊位置滑回。實際雙人瀏覽器流程含射擊期間的 3.3 秒執行緒停頓、恢復後不補播過期事件、設定保存和手機直／橫向觸控。

本機三房／32 真人／48 參與者、20 秒合成伺服器測量：單核估算 25.2%，tick P95 33.70ms、最大 38.98ms。不同本機負載不可直接視為正式主機回歸；固定步長仍為 50ms，正式發佈需完整 CI 與健康檢查成功。


## 移動射擊回歸

補上原生兩指移動／拖曳射擊、獨立觸點取消、連續身體命中範圍、兩端幾何一致、畫面補間、未確認輸入回放與受限畫面回看測試。固定 16 角色／40 補給／4 個射擊來源時，將彈著位置放到鏡頭內，最多桌面 49／手機模擬 46 次繪製，射擊期間新增 GPU 緩衝仍為 0，彈著效果固定十二個槽位。

在同機相鄰執行的 3 房／32 真人／48 參與者、20 秒合成負載中，正式版 `068f58d` 單核估算 22.0%、tick P95 30.61ms、最大 38.52ms；修正版 21.7%、P95 28.38ms、最大 32.86ms。屬單次本機測量，不能視為穩定的百分比加速或正式主機負載；重點是新增命中檢查後仍守住 50ms 步長預算，並保留固定資源上限。

移動對射 fixture 使用雙向各 90ms 延遲、零散布、程式準星追蹤來隔離登記問題。此次有補償為 4 發／4 次命中，對照無補償為 6 發／0 次命中；前者因目標淘汰而較早結束。這不是一般遊戲勝率／命中率，正常遊戲仍保留原散布、瞄準與移動規則。

正式成品回歸另外遇到搖桿按住 500ms、放開後固定等 200ms 的取樣在 CI 偶發尚未觀測到有效移動；當時連線正常且重建原地圖確認前方沒有障礙。原生搖桿測試改成等按住輸入進入通道、伺服器確認對應序號且實際位移超過原有 .4m 門檻，再放開並等待同連線釋放輸入被確認。與射擊測試一樣依真實協議／狀態驗證，而非固定牆鐘睡眠；仍使用原生觸控、有限等待，未降低位移要求或重試整個動作。失敗附件另保存最近八十筆原生 pointer 生命週期事件，便於區分輸入與伺服器問題。
