# 荒島行動

楠團原創的小型第三人稱 3D 大逃殺；真人開房、可由 AI 補滿 16 人。它參考大逃殺的搜刮、掩體槍戰、縮圈與最後生還者循環，不是 PUBG 官方產品，也不是完整 PUBG 的一比一移植。角色、武器造型、海角島地圖與 HUD 都由本專案程式建立，未使用對方商標、地圖或遊戲素材。

## 第一版邊界

- 每房最多 16 人；開房時可選 AI 補位或純真人，純真人至少兩人。只有房主開始，不要求每個人先按準備。
- 4 秒倒數、7 秒空降。AI 在落地後有 6 秒不開火的搜刮準備期。落地後拾取腳邊的手槍補給，或探索聚落取得衝鋒槍、步槍、狙擊槍、彈藥、護甲、頭盔與急救包。
- 每人兩把槍，彈匣與備彈獨立，射速／傷害／換彈時間由伺服器設定。牆壁、岩石、樹幹阻擋子彈與角色，第三人稱相機另有避牆。
- 頭部命中提高傷害；頭盔抵消一次部分頭部傷害，背心以護甲耐久吸收部分傷害。急救需 3 秒、恢復 60 點生命，槍擊可中斷；換彈與治療不能射擊。手榴彈有 2.2 秒引信、10 公尺爆炸半徑，掩體可阻擋爆炸。
- 安全區持續縮小且圈外扣血。最後一人獲勝；最長約 5 分半，超時多人仍存活則明確和局。
- 不收取、投注、轉移或派發點數，不保存競技排行。銀行、錢包與牌桌完全分開。
- 不包含載具、百人戰場、組隊倒地救援、PUBG 地圖／角色、完整槍械配件與官方競技反作弊。
- 戰局在記憶體，伺服器重啟會清除，恢復時核對成員資格後回到選房，不對已消失的房間無限重連；純娛樂模式不影響任何點數。這個限制直接寫在操作說明。

## 入口與操作

大廳「選擇遊戲」前有荒島行動入口，路由為 `#battle`，不增加手機底部主導航數量。開房產生六位房號；同站已登入玩家可複製房號、輸入加入或從開放列表進入。未登入、已封鎖帳號或不合法來源均不可加入 WebSocket。

手機射擊支援點按單發、按住連射；短按會保留到下一次輸入送出，伺服器也保留同一步內的扳機按下，避免快速放開時漏發。仍依武器射速、換彈／治療與彈藥限制判定，不補發冷卻中被拒絕的射擊；斷線、暫停或切 App 清除未送出的按鍵。徒手時顯示「先撿槍」並提供拾取提示。

電腦 WASD 移動、滑鼠轉向、左鍵或 F 射擊、右鍵瞄準、E 拾取、R 換彈、H 急救、G 手榴彈、C 蹲下、Shift 衝刺、空白鍵跳躍、1／2 換武器。點畫面可鎖定滑鼠，Esc 開選單；不支援鎖定時可拖曳轉向。手機左搖桿、右側拖曳視角與獨立射擊／戰術按鈕，直向與橫向均可用。音效由使用者自行開啟，不自動播放或要求麥克風。語音入口沿用既有全域語音，不建立第二套語音服務。

選單不暫停線上戰局。淘汰或結束會關閉戰鬥選單，只提供結果／觀戰，不讓「繼續戰鬥」與結算層互相遮擋。3D 重載超過 25 秒仍依正常離線規則淘汰；恢復的是同一角色與結果，不能藉重新整理復活。切 App 或斷線先清除輸入；回來重連、沿用原角色與伺服器彈藥。25 秒未恢復則淘汰。每局有獨立 round_id，換局後忽略舊局快照。重新整理後可從「回到我的戰場」恢復；同帳號新分頁取代舊連線，舊分頁明確顯示接管提示，不互相無限搶連。明確離開會立即淘汰，若正在對戰會先顯示確認。等待房主離開時自動轉移房主。

## 架構

| 檔案 | 責任 |
| --- | --- |
| `battle_engine.py` | 固定步長物理、地圖碰撞、射線命中、AI、背包／補給、縮圈與勝負 |
| `battle.py` | 有界記憶體房間、成員與單連線租約、模擬時鐘、WebSocket 讀寫／限流 |
| `server.py` | 既有 session、帳號資格與 Origin 驗證，戰場 HTTP／WS 路由 |
| `static/battle.js` | 開房、列表、HUD、重連世代、手機選單及既有 SPA 生命週期 |
| `static/battle-scene.js` | 延遲載入 Three.js、原創低多邊形場景、批次角色動畫、補間／預測、特效池、鍵鼠／多點觸控、音效 |
| `static/night.css` | `#battle-console` 專屬樣式及大廳入口，沿用唯一樣式檔 |

傳輸只接受有限範圍與有限長度的操作意圖（方向、視角、按鍵、序號），不接受客戶端位置、生命、傷害、彈藥或結果。移動採固定 50ms 步長；對角線正規化、逾時輸入歸零。伺服器先更新所有人的位置，再一併判定同一步的射擊傷害，允許同時淘汰，房主不因插入順序固定而先阻止別人開火；圖像預測不能改變勝負。存活者快照只包含附近且未被掩體遮擋的敵人，私有彈藥只在本人的 `self` 欄位；牆後射線事件不洩漏位置。這些是第一版限制驗證，不代表已達商業射擊遊戲的反作弊強度。

高頻操作不進 SQLite、`WRITES` 或牌桌 SSE。模擬使用獨立鎖與時鐘，每個收件人只留最新一份快照；慢連線不累積歷史幀、不阻塞模擬。WebSocket 使用既有標準庫 frame 解碼，另有戰場獨立文字協定、訊息大小／速率限制、5 秒帳號重驗及固定心跳。最多 3 房、32 條真人連線；等待斷線成員 90 秒清理、結束 180 秒清理、房間最長閒置 600 秒。

`ClubBattle.unmount()` 會取消 timer／事件監聽、關閉 socket、解除滑鼠鎖／全螢幕、停止動畫並釋放 WebGL 幾何、材質與 context。房間資料先於 3D 引擎載入，恢復入口不依賴圖形編譯後才查詢；引擎未完成前禁止加入。牌桌、大廳、銀行不載入 Three.js。圖形引擎不支援時提供明確錯誤與返回入口，不用靜態圖假裝已進遊戲。

## 視覺規格

海角島以乾燥草地、海岸、混凝土聚落與三種屋頂顏色區分地點，使用原生幾何、實例樹木／建築，沒有大型貼圖或外部模型下載。此模式與牌桌的奶油色殼層分開，以減少戰鬥時的裝飾干擾。

| 色彩 | 用途 |
| --- | --- |
| `#172c2d` | 戰場介面底色 |
| `#15292d` | 半透明戰術面板 |
| `#edd28d` | 開局與主要操作 |
| `#f2efdd` | 文字與生命狀態 |
| `#6e824f` | 海島草地 |
| `#367e95` | 海面與遠景 |

沿用 Segoe UI／Microsoft JhengHei，沒有外部字型。大廳是背景戰場＋左側遊戲名稱＋右側開房欄；遊玩時讓出整個視窗，只有存活人數、縮圈、小地圖、準星、生命與武器資訊。手機主要控制至少 44px、按鈕位置穩定並保留安全區。減少動態時停用鏡頭裝飾擺動／傷害閃光，保留遊戲必需移動。手機 DPR 上限 1、電腦 1.25，正常目標 60fps；減少動態時目標 30fps。持續負載偏高時自動降低解析度，最低 DPR .75，必要時改為 30fps；隱藏分頁暫停繪製。以批次接地陰影取代即時陰影。這些是負載策略，不是所有實體裝置的幀率保證。

- [PUBG 官方安全區說明](https://support.pubg.com/hc/en-us/articles/115004168813-What-is-the-blue-circle)：圈外傷害概念參考。

合成帳號的實際畫面：[桌面戰場](screenshots/battle-desktop.png)、[手機直向](screenshots/battle-phone.png)。

CI 的 3D 瀏覽器流程獨立成 `battle` job，正式 release 同時依賴 core、browser、battle 成功；軟體 GPU 的引擎首次啟動另留 60 秒預算並保存實際耗時，互動預設仍為 15 秒。射速以伺服器時間核對，放開按鍵後等待原輸入序號回應，再確認彈藥停止減少，不用 CI 指標事件派送所耗的牆鐘時間假裝真實按住時長。

## 順暢度與恢復

角色以十五組共用 InstancedMesh 繪製（含四種武器與近距離手部），九種補給各一組並共用光柱／底盤；48 段彈道與 6 個爆炸效果重用固定資源，不隨每一發子彈建立 GPU 幾何／材質。近距離槍口曳光與聲音提供本機即時回饋，命中、傷害與彈藥仍由伺服器決定，回傳時避免重播同一個本機特效。

相同 seed 的重連保留地圖與視角，第一份快照只恢復狀態，不補播歷史彈道。新回合才重建場景。移動在本機預測、收到新快照時處理誤差，不再每一幀向同一筆舊位置拉回；落下與其他玩家位置做補間，鏡頭直接跟隨當前轉向。靜態掩體依空間區塊查找，保留原有碰撞範圍。小地圖／方位文字降低更新頻率，命中特效不強制同步排版。

`test:battle-perf` 使用固定的 16 角色、40 補給與 4 人射擊合成場景，檢查繪製次數、GPU 緩衝重用、同圖重連、轉向構圖、停止移動不被舊快照拉回、碰撞索引等價與本機特效不更改彈藥；輸出在 `artifacts/battle/performance/`。數值屬 Chromium 軟體 WebGL 的比較測量，不能換算成實體手機 FPS。

本次前後數據與限制：[順暢度驗證報告](BATTLE-PERFORMANCE.md)。

前景執行緒延遲超過 1.2 秒時先清除舊輸入，保留 1 秒讓已排隊的快照被處理；真正沒有狀態超過 3 秒仍會重連。這避免 CPU 忙碌被誤判為網路中斷，不會在沒有新狀態時繼續發送舊射擊。


## 動作與畫面打磨（2026-10-29）

- 上一輪角色使用 42 個共用幾何部件、四個繪製批次（本輪美術資源規格見下節）；補上膝肘關節、腳底著地、步態混合、呼吸、蹲姿、換彈手勢與傘繩收傘。四款武器的槍身長度、彈匣、槍托和瞄鏡區分；裝備顯示仍以伺服器狀態為準。
- 建築改成雙坡屋頂、窗框與門框，補給箱增加束帶；地面、牆面、道路、屋頂、海面使用一次生成並重用的 128×128 原創材質。沒有外部素材下載、逐幀圖片生成或即時陰影。
- 第三人稱準星由相機中心射線找最近的可見目標／掩體，再傳送有限範圍的瞄準位置。伺服器從角色自己的射擊高度重新計算射線，保留散布、射速、彈藥、射程與掩體驗證；座標不完整、非有限、背向或越界的操作會被拒絕。舊版無瞄準位置的輸入仍沿用 yaw／pitch。
- 瞄準的相機距離、肩側偏移與視角依時間混合，轉向保持直接跟手。命中數字與爆頭提示只能由伺服器事件產生；聲音重用同一段噪音緩衝，最多八組同時播放，避免大量射擊堆積音效。
- 每幀最多套用一份最新快照。以伺服器時鐘估計排隊延遲，略過落後超過 700ms 的快照；事件總年齡超過 500ms 不補播。恢復連線的第一份狀態仍不播放歷史特效。
- 選單提供自動／流暢／清晰畫質和 0.5–1.8 倍轉向靈敏度，只存於本機。清晰模式提高解析度，流暢模式限制初始解析度，自動與流暢模式仍可依負載降畫質；不宣稱所有裝置固定 60 FPS。

驗證包括近／遠／蹲姿準星命中、掩體與射程不可繞過、不合法瞄準輸入、平順瞄準過渡、武器抬頭方向、手機設定保存，以及真實射擊期間 3.3 秒主執行緒停頓的恢復。多人效能測試仍使用原本的固定 GPU 資源與繪製預算；實體手機長時間熱機與行動網路尚須實機驗收。


## 移動射擊修正（2026-10-29）

手機可用兩拇指操作：左手移動，右手按住射擊並拖曳瞄準；各觸點獨立取消，不讓其他手指的取消事件停掉搖桿或扳機。普通拖曳降低過敏程度，精準瞄準再降至一半。射擊按鈕明示拖曳操作、提高對比，換彈／治療時顯示當前狀態。瞄準鏡頭接近人物時隱藏自己的頭／軀幹，保留手部和槍械；其他玩家仍看見完整角色。

身體改用連續垂直膠囊＋獨立頭部，補上原本上胸／頸部附近兩個球形範圍之間的空隙。歡迎封包提供同一份命中尺寸給客戶端；準星預估和伺服器使用一致的形狀。普通站立射擊的相機中心線對齊角色射擊高度，不再額外抬高 0.6 公尺。準星變金僅表示對準可見目標，真正命中與傷害仍需伺服器確認。

其他人物以六筆快照緩衝，在伺服器時間軸上保留 80ms 補間，最多外推 80ms 後停止；不在每次回報重新向舊目標拉近。自己的移動記錄最多 32 筆已送出輸入，收到伺服器序號後僅回放未確認部分，再平滑修正誤差，避免衝刺／停步被延遲座標反覆拉回。步頻與步幅跟隨實際速度，區分側移／後退，換彈姿勢與後座力依時間平滑。

伺服器保留十二幀人物位置歷史。客戶端攜帶準星畫面的 tick／時間，必須對得上這條連線在同一回合最近實際發送的八份快照之一，並落在該快照前 150ms／後 80ms 範圍；最多回看 **400ms**，超時／未知畫面維持現在位置判定。歷史姿勢只用於射線測試，不移動、復活或傳送人物，不改彈藥、射速、散布、射程與掩體檢查；重連、換局不能挪用其他連線／回合的畫面證明。此為有界延遲補償，不代表完整競技反作弊。

伺服器射擊事件另外標示打中人物／掩體／未命中，客戶端以十二個共用彈著效果提供確認，不在本機預先判定傷害，也不逐發增加幾何或 GPU 緩衝。

`tests/browser/battle-accuracy.cjs` 用隔離伺服器及兩個真實登入客戶端，人工加入雙向各 90ms 延遲，射手與目標都移動。只有測試 fixture 關閉散布並用程式保持準星對準，以隔離命中登記問題；正常遊戲未關閉散布或加入自動瞄準。同一起點和延遲另跑停用補償的對照，結果保存在 `artifacts/battle/accuracy/`，不能用單次結果宣稱一般玩家命中率。


## 海島戰術美術（2026-10-29）

`static/battle-art.js` 集中建立原創的色彩、共用模型和一次生成的材質；`battle-scene.js` 負責狀態、骨架姿勢、相機與批次繪製。所有資產隨網站交付，沒有外部模型、圖片或字型下載。

- 四款槍有各自的槍托、彈匣、護木、準具與槍口；狙擊槍另有瞄鏡／腳架。細節先烘成帶頂點色的共享幾何，遠近人物與地面槍械共用來源。槍口閃光／彈道依各槍模型位置顯示，命中仍由原伺服器射線決定。
- 人物共 44 個可見性／骨架部件，服裝、膝部護具、鞋底、手套、護目鏡、頭盔與背包增加層次；背包的口袋、束帶、睡墊及背心合併成一個模型。瞄準近景使用相機相對的手部與武器顯示模型，隱藏自己的完整軀幹，其他玩家仍看見完整人物。這個模型不決定射擊位置或命中。
- 九種地面補給具有對應實物輪廓：四款槍、彈藥盒、綠色醫療箱、護甲、頭盔、手榴彈；保留分類色底盤與淡光柱。總數最多 256，最多十六人，每種槍的持有模型容量十六，第一人稱手部各一。
- 房屋依聚落搭配灰泥／磚牆／木質地板、不同屋頂色，增加窗框、窗台、百葉窗、排水管、門檻及編號牌；靜態細節合併繪製。補給箱有加固角、束帶和標籤，海面有輕微紋理漂移與沿岸白沫。七張 256×256 重複材質、64×64 接地陰影與一張 512×256 門牌圖集取代大型下載素材；減少動態設定停用漂移與光柱呼吸。
- 保留原有物理與掩體。地圖 `tree` 實際只有低矮方形碰撞範圍，因此可達區域改成對應範圍的低灌木，避免看似可躲在高樹後卻被穿透；高樹留在實體海岸之外。房門與門檻保留可通行的開口，屋外窗戶仍只是裝飾，不開放新的射擊通道。

微小／薄片零件使用普通方盒，較大的輪廓才加倒角；不使用即時陰影或逐幀生成模型。每次切換新地圖釋放舊幾何、獨立材質與門牌貼圖，武器／補給保留共用。靜態資產使用版本查詢與 ETag／no-cache；入口 no-store，避免新版場景載入舊模型模組。手機兩拇指操作、精準轉向、移動預測、插值及受限命中回看沿用原規則。
