# 設計系統與互動約束

## 方向

深色牌室、溫暖金屬色、低干擾操作、精緻微縮會所。先維持辨識與操作一致性，再探索視覺方案；設計稿可以提出替代方向，不需受既有所有裝飾限制。

目前桌機使用左側欄，手機使用底部導航。頁首共用錢包、連線狀態、語音與個人入口。牌桌仍在原網站同頁路由，避免因換頁斷音或重建連線。

## 現有 token

下表取自唯一樣式來源 night.css 的 :root；所有元件使用同一套現行 token，實際效果可由 computed style 核對。

| token | 值 | 角色 |
| --- | --- | --- |
| --night | #0e131b | 頁面底色 |
| --panel | #19232f | 卡片／面板 |
| --panel2 | #202d3b | 第二層表面 |
| --line | #2c3947 | 分隔線 |
| --ink | #f2f4f7 | 主要文字 |
| --muted | #aab6c5 | 次要文字 |
| --subtle | #8f9eaf | 弱資訊 |
| --gold | #e6c39a | 會所與重要標記 |
| --night-accent | #a8c8e7 | 藍色選中／錢包重點 |

基礎字體是 Segoe UI／Microsoft JhengHei／Noto Sans TC／sans-serif。現階段沒有外部字型下載。資訊文字以可讀性為先，避免大量無助操作的小字；按鈕用具體動作，如「確認下注」「從錢包帶入籌碼」。

## 元件清單

- AppShell：桌機側欄、手機底部導航、頁首、理性遊戲提醒。
- GameCard／RoomCard：遊戲封面、桌狀態、座位容量、進入按鈕。
- WalletFunding：錢包餘額、本桌籌碼、自訂／全部帶入。
- BetStepper：金額輸入、加減、快捷值；輸入不是提交。
- ActionPanel：當前玩家、倒數、合法動作、送出回饋。
- PlayerIdentity：暱稱、頭像、稱號、輕量特效。
- Cards／Dice／Wheel：結果資料與展示動畫分開。
- VoiceControls：加入、靜音、收聽、成員、裝置設定。
- EstateCard：名稱／等級、四級建築、獨立升級入口、員工動畫。
- Dialog／Toast／InlineStatus：確認、錯誤與持續狀態，避免同一訊息四處重複。

上述是設計上的元件分類，尚未全部抽成獨立程式模組；實際檔案見 FRONTEND-MAP。

## 響應式與可及性

主斷點為 760px，另有 1100px、640px、360px 等局部規則；不要假定只有一個手機斷點。設計交付至少提供 393×852、320×844、844×390、1366×900，並檢查 768px 過渡。

觸控操作至少 44×44 CSS px，主要遊戲動作建議 48px。金額和選牌不能只靠 hover。狀態不可只用紅綠表達，應同時有文字／圖示。保留 :focus-visible、label、dialog 標題與鍵盤關閉。長暱稱必須換行或有可理解的截斷，不得撐出整頁。

圖片預留 aspect-ratio；提示、送出中與結果不要把開始按鈕推走。會所手機版的標題和等級在圖上方，建築圖 3:2、按鈕在下方，不與房子重疊。

## 動畫與效能

動畫表達已提交結果，不決定勝負，不阻擋下一次合法操作。使用 transform／opacity、小範圍圖層及有限佇列，尊重 prefers-reduced-motion；離屏與背景頁暫停裝飾。員工在 SVG 層行走，建築仍為 WebP，不是執行時 3D 引擎。

不能為了「展示完」延後 HTTP、改回每秒全頁輪詢，或加重複 setInterval。檢查連續拉霸、發牌、分牌、快速切回頁面與語音開啟時的實際互動。

## 牌桌導航與回饋契約

所有遊戲（含麻將）由 game.js 的 tableHeading 產生同一組牌桌導航：

| 動作 | 位置／行為 | 等待及失敗 |
| --- | --- | --- |
| 回大廳 | 標題左側的文字連結；不送離桌，不改目前座位；同頁路由 | 本筆操作未確認時保留原頁與收據 |
| 離開牌桌 | 標題右側唯一入口，手機也保留文字，至少 44px | 確認框只解釋本款遊戲；預設焦點在「繼續留桌」；失敗留桌，確認成功才回大廳 |
| 結束牌桌 | 僅等待中的房主可見，收在房主管理選單 | 明示所有人離桌；保留 API 權限檢查；確認前重驗桌號／狀態 |
| 回到牌桌／查看結算 | 保留座位時，大廳及其他功能頁的共用提示列 | 離桌結算中改顯示「查看結算」，不承諾即時退回 |
| 確認原操作 | 原操作結果不明時顯示 | 使用同一 operation_id；不新增下注；離桌收據稍後由推播確認也能回大廳 |

同一張桌不重複放離桌／結束入口。聊天與紀錄在手機可用圖示，但保留可讀名稱；離桌不可縮成只有圖示。頁面底部保留遊戲紀錄摘要，管理不與遊戲主動作並列。

操作回饋放在動作後，避免提示把正在按的按鈕推走。輪盤／骰寶把回饋放進既有底部押注列，預留固定 56px 狀態區，長訊息可捲動、確認原操作的觸控範圍至少 44px。拉霸沿用自己的回饋與演出；不改收據、動畫揭曉或交易時序。

確認框打開後若使用者已換桌，舊確認不能套用到新桌。送出中及收據結果未知時，連結、程式導航與瀏覽器上一頁皆保留原操作所在牌桌；重新整理仍走既有伺服器恢復規則。

## 補給任務入口

桌機左側與手機底部均提供「補給任務」，維持手機五個主要導覽項目；可領取數由現有每日／每小時及任務狀態計算，不增加輪詢。大廳標題旁另有快捷入口。#rewards 常駐展開補給與今日任務，頂部可直接跳到任務或前往外觀收藏。#collection 深層連結保留，任務只在補給頁顯示一份。錢包每日 1,000、每小時 200 的規則與會所收益均未調整。

## Android 版面與主次操作

App 保持單一原生 WebView，安全區由 Flutter 處理，尺寸與鍵盤變化不重載遊戲或重建語音。原生視窗底色與系統列保持深綠，錯誤頁可在短螢幕捲動。金色保留給開始／下注；牌桌返回採安靜文字樣式，工具列採低干擾描邊，離桌以酒紅辨識。導覽仍是相同動作與 44–48px 觸控目標。

## 楠團漁港

延用奶油、金框與深綠品牌；海景獨立使用青藍景深和手繪感向量魚，不加大型貼圖或執行時3D。桌機海面與操作並排；手機魚種與點數並排，發射鍵緊接海景，狀態區固定高度，魚簍與圖鑑在下方。金色用於主要拋竿／收竿／發射，魚簍出售為次要按鈕。入口在大廳，保留手機五個主導航。

模式切換不重建整站，SSE不重建Canvas；離頁停止RAF／計時器，減少動態偏好提供靜態海景與文字魚訊。炮彈點數可直接輸入、加減或快捷選擇；改金額不重建按鈕，鍵盤焦點在更新後保留。原操作未確認時只提供核對原回執，重新整理仍從本人sessionStorage恢復，不自動再下注。

## 桌機牌面可讀性

1024px以上的即時牌桌使用桌機牌面參數；手機、窄平板及原有手機橫向規則維持原尺寸。德州公共牌依桌面寬度60–84px，個人扇形手牌120px；21點個人124px、莊家112px、同桌96px；大老二手牌104px、桌面牌84px；百家樂120px；射龍門依可用空間80–128px。尺寸仍維持2:3比例，照片與牌角同一張表面。

德州增加牌桌高度與公共牌／手牌間距，仍是同頁的牌桌加操作欄。21點多張與分牌、百家樂第三張依容器寬度重疊，保留牌角；大老二用`data-card-count`和外部CSS調整實際剩餘牌數的展開，不使用被CSP擋住的行內樣式。正常桌機寬度可顯示13張手牌；較窄容器仍可水平捲動，保留至少40px的牌角曝光。

## 楠團銀行

銀行沿用現有 token、按鈕與數字輸入，不載入外部字型或新圖。桌機左側增加銀行；手機五項底部導航維持，由頁首錢包／補給頁進入。存款、待還款與可用錢包分開顯示，操作區保留固定狀態高度；借款先看條件再確認，未知結果只核對原回執。規則收在可展開區，表單與推播更新不搶輸入焦點。詳見 [銀行規格](BANK.md)。
