# 頁面設計協作工作單

協作者：livangvang；專案擁有者：leochao1212。目標是提高桌機與手機的精緻度、清楚程度和實際操作效率。先在設計分支提出方案，再透過 PR 討論，不直接替換正式網站。

## 建議批次

| 順序 | 頁面 | 要解的問題 | 交付 |
| --- | --- | --- | --- |
| 1 | 共用殼層＋遊戲大廳 | 主要入口清楚、正在玩的桌容易找、資訊不堆疊 | 桌機與手機完整稿＋導航元件 |
| 2 | 我的會所 | 四級外觀有差異、員工自然動態、收益與升級易理解 | 四級外觀組合＋升級／派遣狀態 |
| 3 | 牌桌共用控制＋德州／21 點 | 看牌、看同桌、改金額與提交順手 | 正常／輪到你／等待／重連／結算 |
| 4 | 小遊戲 | 開始鍵靠近遊戲，結果不改尺寸，不強迫看完動畫 | 拉霸、輪盤、骰寶、射龍門樣式 |
| 5 | 個人頁、排行、收藏 | 帳號管理、資金水位、稱號可辨識 | 自己／其他人、長名稱、空狀態 |
| 6 | 錢包、管理後台 | 移轉與調整語意清楚、確認與結果一致 | 表單、驗證、成功／失敗狀態 |

## 必須保留的產品行為

- 任意註冊人數；牌桌人數依遊戲，兩者分開。
- 一般桌取消通用準備步驟；不要把「準備一次、再按開始」加回所有遊戲。
- 21 點每人可自訂偶數下注，等待時可見每人金額／確認狀態；最後一人確認自動發牌，修改下注先取消確認。
- 21 點同桌玩家的牌直接可見；莊家底牌依規則保密。
- 德州有自己握兩張牌的辨識感，桌上與手中不要混淆。
- 入桌與補碼的錢包入口明顯；可自訂金額或全部帶入。
- 聊天與語音可在未入座時使用；路由切換不斷掉已加入的語音。
- 結果回饋不改拉霸機台寬度或讓操作按鈕跑位。
- 手機會所圖片不被名稱、等級、升級按鈕蓋住。
- 純虛擬點數；不新增充值、提款或現金兌換介面。

## 每頁設計需要的狀態

基本、載入、空資料、長暱稱／長結果、資料多、操作等待、成功、可重試失敗、離線恢復、沒有權限。遊戲另含觀戰、未入座、輪到自己、等待別人、籌碼不足、暫離、結算後下一局。

每個狀態指出：主要動作、次要動作、資料來源、是否可操作、焦點位置、手機捲動與底部安全區。不要只交一張好看的正常狀態封面。

## 驗收方式

1. 在本機合成帳號實際操作，不使用正式帳號和玩家資金。
2. 393／320px 直向、844×390 橫向、768px 過渡、1366px 桌機無整頁水平捲動。
3. 操作、提示與圖片沒有非預期遮擋；送出中不讓主按鈕換位置。
4. HTTP／SSE 更新保留草稿、選牌、展開狀態；重連不重複扣點。
5. 語音持續、減少動態可用、觸控／鍵盤皆能完成核心流程。
6. PR 放桌機與手機前後截圖，說明影響的頁面、互動契約及測試。

## 設計與規則的分界

改色彩、間距、版面、文字與裝飾動態，可在設計分支完成；改派彩、抽牌、勝率、回合時限、錢包寫入、認證與權限，需拆成獨立功能 PR 並加對應規則測試。

目前 CSS 存在多層歷史覆寫，可以逐頁整併，但請先保留現有 DOM 識別與事件契約。完整前端重寫、多人架構重寫或更換資料庫不包含在這份頁面改版工作單中。
