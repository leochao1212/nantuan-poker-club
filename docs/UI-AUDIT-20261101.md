本輪先比對成熟遊戲的公開介面，再以目前專案建立隔離資料庫、合成帳號與遊戲房間。修正位於 `ui/readability-audit-20261101`，尚未部署正式站；未修改金流、獎勵倍率、機率或玩家資料。

## 沒有誤判成缺陷的項目

- 頂欄視覺按鈕雖多為 32–34px，原程式已用偽元素擴大點擊區。本輪在 320/393px、Chromium/WebKit 實測有效範圍至少 44px、四角均命中原按鈕，所以沒有為了外觀尺寸盲目放大整排。
- 320px 交易頁的文字放大測試曾在圖表重排前報溢出；等待 ResizeObserver 重排後通過。這是測試同步問題，沒有當成正式站缺陷修改。
- 本輪覆蓋畫面沒有發現圖片載入失敗或整頁橫向溢出；不等於所有帳號、連線條件與遊戲狀態都沒有問題。

## 驗證與證據

- 修改前：既有完整版面 suite 的 21 個頁面、314 個視窗組合通過，包含 11 種遊戲、手機直橫向、平板及桌面；同時額外記錄按鈕尺寸與實際畫面。
- 針對本輪修正：大廳、獎勵、收藏、會所、銀行、樂透、交易，共 7 頁 × 4 寬度（320/393/768/1366）× Chromium/WebKit = 56 組。比較修正前後對比與內距、檢查圖片和溢位。
- 再驗 14 組 320px、主要內容文字放大 130% 的情況，等待圖表自動重排；這是文字放大測試，不宣稱等同所有瀏覽器／系統的 200% 縮放或實體手機測試。
- 驗證收藏入口直接選中稱號頁；既有領獎流程 4 組桌面／手機測試通過，包含失去回應後重試、原地裝備與不重複領取。
- JavaScript 語法及 146 個 UI 素材指紋通過。沒有改後端，因此沒有重跑無關的完整 Python 測試或部署。
- 重跑指令：`npm run test:readability`、`node tests/browser/reward-hub.cjs`；完整牌桌版面可用 `npm run test:layout`。
- 本機原始證據：`artifacts/ui-audit-20261101/`、`artifacts/ui-readability/before/`、`artifacts/ui-readability/after/`。這些目錄不提交；測試腳本會重新產生修正後證據。

## 後續設計優先順序

1. **牌桌資訊層級**：射龍門的機率、返還率、保護及稱號說明同時出現，畫面讀取負擔偏高。下一輪可把「本次下注、可得／可能失去、確認動作」固定在操作區，計算細節放可展開說明；應另做遊戲中各階段驗證。
2. **牌面辨識**：德州與大老二的人像牌有風格，但手機上數字／花色與裝飾競爭。建議提供清晰牌面模式或較大的角標，需保留現有牌背及玩家外觀選擇，不在本輪直接換美術。
3. **會所主要動作**：目前會所首屏偏重場景與升級，收益和派遣較下方。可另做「領取／派遣」操作摘要，但不要再重複增加一套獎勵領取入口。

上述三項是後續設計建議，不列為本輪已實作。所有截圖來自合成帳號；沒有使用正式玩家的私人資料。
