# 釣魚順暢度與銀行整合

街機原本在整張海景 Canvas 建立魚場裁切，魚、標籤、炮彈每次還原繪圖狀態都繼承裁切。本機 Chromium 手機高負載測得明顯合成成本；改為可重用的獨立魚場 Canvas，以邊界裁切再合成回海景，沒有改位置、碰撞、素材、子彈或派彩。離頁釋放圖層。

舊排程繪圖後以當前時間重設基準，遇到 33ms 邊界抖動會漏畫；改用相位累積，每次 RAF 最多畫一次，維持正常 30fps／減少動態 20fps 上限，不追補積壓幀。張力 HUD 仍獨立 60／20Hz，背景與離屏維持暫停。

同機合成場景：18 尾魚、4 人、48 筆飛行／命中炮彈；手機 393×852、DPR 3，繪圖倍率沿原上限 1.5；每段 3 秒。這不是實體手機幀率保證。

| Chromium 情境 | 修改前 | 修改後 |
| --- | --- | --- |
| 手機一般每幀中位耗時 | 28.5ms | 12.4ms |
| 手機一般每幀 p95 | 33.5ms | 14.8ms |
| 手機一般繪圖率 | 23.3fps | 25.4fps（當次可用 RAF 約 25.3Hz） |
| 手機減少動態每幀中位耗時 | 31.1ms | 9.4ms |
| 桌機一般繪圖率 | 22.9fps | 30.0fps |
| 桌機一般每幀中位耗時 | 8.0ms | 9.2ms |

桌機多一次圖層合成，單幀成本略增，但排程漏畫改善；低階手機仍可能達不到 30fps。原始結果保留在本機忽略的 `artifacts/fishing-performance`。

## 後端負載範圍

現有隔離腳本固定單 CPU 核心，20 人、40 SSE、400 批共 800 發：本輪中位回應 349.12ms、p95 724.72ms、最大 1007.40ms；800 發正確結算，無錯誤或未結算炮彈，扣點與帳本一致。銀行接入後另一輪同規模壓測中位 496.94ms、p95 784.87ms、最大 928.66ms，800 發也全數正確結算。魚場種子與排程會隨測試改變，這兩輪不作為後端速度提升的證據。本次前端修改不宣稱消除了後端碰撞與排隊延遲，也未量到正式手機的對外網路或正式主機 CPU。

執行 `python scripts/bench-fishing.py`，僅開本機隔離服務，不接正式資料庫。效能量測勿同時跑其他壓測，不把不同硬體數字直接當成同一基準。

銀行採站長指定存款日息 0.5%、貸款日息 1.5%，與遊戲派彩分開，見[銀行規格](../BANK.md)。

前端量測可用 [render benchmark](../../scripts/bench-fishing-render.cjs)：`node scripts/bench-fishing-render.cjs`，或第一個參數指定要比較的本機 scene.js，第二個參數指定結果 JSON 檔名。輸出皆在忽略的 artifacts/fishing-performance，PERF_ENGINE／PERF_DEVICE 可縮小檢查範圍。
