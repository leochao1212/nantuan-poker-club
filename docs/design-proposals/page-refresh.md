# 頁面改版草案 · 第一輪討論

這份草案放在 `design/page-refresh`，供 leochao1212 與 livangvang 在草稿 PR 討論。系統架構、路由和資料契約以 [前端地圖](../FRONTEND-MAP.md) 為準；完整驗收條件見 [設計工作單](../PAGE-DESIGN-BRIEF.md)。

## 要解的實際問題

目前大廳入口與開桌列表需要更清楚；手機常需要捲動才找得到主要操作；遊戲提示、結果和動畫可能擠動按鈕。會所要讓四級建築和員工有明顯差異，也要保留手機圖片與升級鍵的分層。德州應看起來像自己握著兩張牌；21 點需要能清楚看見同桌下注確認和每人的牌。大廳、觀戰及桌內共用語音狀態要可見。

## 可比較的視覺方向

| 方案 | 視覺語言 | 適合的頁面 | 要確認的風險 |
| --- | --- | --- | --- |
| 深夜牌室 | 深藍黑底、溫金與少量紅色提示，桌面材質和聚光 | 德州、21 點、首頁 | 金色控制亮度，文字不能被裝飾吃掉 |
| 都會俱樂部 | 暗色建築、琥珀與青綠分層、較克制的 3D 圖片 | 會所、會員、排行榜 | 圖片下載與動畫須顧及手機效能 |
| 遊戲街區 | 不同遊戲有獨特色彩與圖形，共用穩定操作框架 | 拉霸、輪盤、骰寶、射龍門 | 不能讓同一網站的導航失去一致性 |

建議先以「深夜牌室」作共用殼層，「都會俱樂部」作會所細節，「遊戲街區」只用在各遊戲的主視覺。請先做一頁桌機與手機對照，確認方向後再擴充全部頁面；三種方向都可以修正。

## 第一批交付順序

1. **共用殼層與大廳**：頂部連線狀態、語音、個人資料、主導航、遊戲卡與正在玩的桌。完成 320／393／768／1366px。
2. **會所**：四級圖片、升級預覽、待領收益、員工活動。手機名稱與等級在圖上方，升級按鈕在圖下方。[現況合成截圖](../screenshots/clubhouse-mobile.png)。
3. **牌桌**：德州手牌兩張、公共牌、下注；21 點同桌下注狀態、同桌明牌及莊家暗牌。[桌機測試圖](../screenshots/blackjack-desktop.png)、[手機同桌手牌](../screenshots/blackjack-peer-mobile.png)。
4. **機台**：拉霸、輪盤、骰寶、射龍門。開始鍵位置固定，結果與動畫不改操作區尺寸，長文字不推走按鈕。

每個頁面請提供正常、操作中、網路重連、失敗、空狀態；標出主按鈕、次要按鈕、提示與語音狀態的位置。

## 元件與實作邊界

先提議共用元件：`AppShell`（導航和連線／語音）、`GameEntry`（封面、桌數、入桌）、`ActionDock`（主動作與下注）、`PlayerBadge`（頭像與稱號）、`ConnectionNotice`（重連狀態）。名稱是討論用；實作仍以現有原生 JS/CSS 及 DOM 更新契約進行，不假設已導入框架。

牌局資料由現有 HTTP 與 SSE 決定；設計 PR 不改派彩、發牌、籌碼轉移、身份權限或語音傳輸。21 點每人各自確認下注後才一起發牌；一般遊戲沒有通用「全員準備」。草稿輸入、選牌與展開狀態要在推播時保留。
